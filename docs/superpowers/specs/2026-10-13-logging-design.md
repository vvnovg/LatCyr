# Постоянное логирование с ротацией — Дизайн-документ

**Дата:** 2026-10-13
**Статус:** утверждён

## 1. Цель

У LatCyr нет никакого логирования. Когда что-то не работает у пользователя, причину приходится угадывать. Поводом стал баг «в Claude слово иногда не исправляется, а раскладка не переключается», где по коду можно выдвинуть с полдюжины гипотез и ни одну не подтвердить. Ожидается большой приток пользователей, и поддержке нужен способ быстро найти причину по присланному файлу.

Решение: собственный файловый логгер с ротацией по суммарному объёму, уровнем и лимитом, которые переключаются в меню. Набранный текст по умолчанию маскируется.

## 2. Требования

- **По умолчанию логирование выключено.** Пока его не включили, на диск ничего не пишется.
- Уровни: **Выключено** / **Только ошибки** / **Информация** / **Отладка**. Каждый следующий включает предыдущие.
- Суммарный объём всех файлов лога не превышает выбранного лимита: **10 / 50 / 100 МБ**, по умолчанию 100 МБ. 100 МБ — абсолютный потолок.
- Уровень и лимит переживают перезапуск (`UserDefaults`).
- **Набранный текст в лог не попадает** ни на каком уровне. Вместо слова пишутся его признаки: длина и алфавит. Отдельная галочка «Записывать набранный текст» включает запись как есть на 30 минут. Она не сохраняется: снимается по таймеру и при перезапуске.
- Логирование не должно заметно замедлять ввод. Tap активный (`.defaultTap`), и система ждёт возврата callback'а на каждой клавише. Поэтому файловый I/O в callback'е запрещён, а при выключенном уровне сообщение даже не форматируется.
- Пункты меню «Показать лог в Finder» и «Показать файл исключений в Finder».

## 3. Архитектура

Три компонента. Две чистые функции под юнит-тестами и одна тонкая обёртка над файловым I/O, которая, как остальные обёртки проекта, проверяется вручную.

### `LogLevel`, `LogSettings`

```swift
enum LogLevel: Int, Comparable, CaseIterable { case off = 0, error, info, debug }
```

`LogSettings` читает и пишет `UserDefaults` по ключам `logLevel` (Int, по умолчанию `.off`) и `logMaxTotalBytes` (Int, по умолчанию 100 МБ). Значение лимита вне `[10, 50, 100] МБ` приводится к 100 МБ. Флага захвата текста в `LogSettings` нет: он живёт только в памяти.

### `LogRedactor` (чистая функция)

```swift
enum LogRedactor {
    static func redact(_ text: String) -> String   // "привет" → "[6 cyr]"
}
```

Алфавит определяется по буквам слова: `cyr` (только кириллица), `lat` (только латиница), `mix` (обе), `none` (букв нет). Пустая строка даёт `[0 none]`. Длина считается в `Character`, как `word.count` в остальном коде.

### `Sensitive` и интерполяция сообщений

Текст пользователя передаётся в лог только обёрнутым в `Sensitive`:

```swift
struct Sensitive: CustomStringConvertible {
    let text: String
    var description: String { LogRedactor.redact(text) }  // безопасно по умолчанию
}
```

Тип сообщения `LogMessage: ExpressibleByStringInterpolation` имеет собственный `appendInterpolation(_: Sensitive)`. Только он смотрит на флаг захвата и при включённом флаге пишет текст как есть. При любой другой интерполяции, например в обычный `String`, `Sensitive` выводит маскированный вариант. Забытая обёртка — единственный способ утечки, и ревью ловит её по виду вызова: голая строковая переменная в интерполяции лога.

### `LogRotation` (чистая функция)

Файлы: `latcyr.log` (текущий), `latcyr.1.log` … `latcyr.4.log` (старые, чем больше индекс, тем старше). Всего `fileCount = 5`, лимит на один файл `perFile = maxTotal / fileCount`.

```swift
enum LogRotation {
    /// Нужно ли ротировать перед записью `incoming` байт в текущий файл.
    static func shouldRotate(currentSize: Int, incoming: Int, perFileLimit: Int) -> Bool
    /// Индексы старых файлов (1...4), которые нужно удалить, чтобы сумма
    /// размеров всех файлов (текущий + старые) не превышала `totalLimit`.
    /// Удаляются начиная со старшего индекса.
    static func filesToDelete(currentSize: Int, rotated: [Int: Int], totalLimit: Int) -> [Int]
}
```

Ротация: `latcyr.4.log` удаляется, `i` переименовывается в `i+1` начиная с `3`, `latcyr.log` → `latcyr.1.log`, открывается новый пустой `latcyr.log`. Пустой текущий файл никогда не ротируется. Одна строка, длиннее `perFile`, пишется целиком в свежий файл: `shouldRotate` возвращает `false` при `currentSize == 0`.

`filesToDelete` вызывается при старте логгера и при смене лимита в меню. Это закрывает случай «было 100 МБ, выбрали 10 МБ»: старые файлы под прежний лимит удаляются сразу. Если и после этого текущий файл больше нового `perFile`, он ротируется, а уже ротированный снова проходит `filesToDelete`.

### `FileLogger` (тонкая обёртка)

- Каталог: `~/Library/Logs/LatCyr/` — стандартное место, его видит Console.app. Создаётся при первой записи.
- Вся работа с файлом идёт на приватной последовательной очереди `DispatchQueue(label: "com.latcyr.log", qos: .utility)`. Вызывающий поток, включая callback tap'а, только форматирует строку и делает `async`.
- Размер текущего файла хранится в памяти (инициализируется из атрибутов файла при открытии), чтобы не делать `stat` на каждую строку.
- Ошибки самого логгера (не создан каталог, не открыт файл) проглатываются: логировать их некуда. Логгер становится no-op до следующей смены уровня в меню, при которой пробует открыть файл заново.
- Выключение (`.off`) закрывает файл. Существующие файлы не удаляются: их, возможно, ещё не отправили в поддержку.

### Фасад `Log`

```swift
enum Log {
    static func error(_ message: @autoclosure () -> LogMessage)
    static func info(_ message: @autoclosure () -> LogMessage)
    static func debug(_ message: @autoclosure () -> LogMessage)
}
```

`@autoclosure`: если уровень ниже, замыкание не вызывается, и строка не строится. Это главное, что делает отладочные вызовы в горячем пути бесплатными при выключенном логе. Текущий уровень читается из поля в памяти, а не из `UserDefaults` на каждый вызов. Все вызовы в проекте идут с главного потока, поэтому синхронизация поля не нужна.

## 4. Формат строки

```
2026-10-13T14:02:31.482+03:00 DEBUG [com.anthropic.claudefordesktop] boundary " " word=[6 lat] ru=false variant=pc wrong=true ruScore=0.512 enScore=0.211 convRuScore=0.180 convEnScore=0.447
```

Время по ISO 8601 с миллисекундами и смещением пояса, уровень, bundle ID фронтального приложения (вычисляется только когда строка действительно пишется), сообщение. Одна строка — одно событие, переводы строк внутри сообщения заменяются на `\n`.

При каждом открытии файла (старт приложения, включение логирования) пишется заголовок уровня `info`: версия и билд LatCyr, версия macOS, текущий уровень и лимит, состояние разрешений (Accessibility, Input Monitoring), список включённых раскладок (input source ID), содержимое `hybrid-apps.txt`, число слов-исключений. Эти данные поддержка запрашивала бы первым делом.

## 5. Что логируется

**error**
- Не удалось создать event tap (`tapCreate` вернул nil). Сейчас `start()` молча выходит, а меню показывает «включено».
- Tap отключён системой (`tapDisabledByTimeout` / `tapDisabledByUserInput`) — с типом события.
- Коррекция решена (`isWrongLayout == true`), но не применена ни через AX, ни через fallback — с причиной: нет fallback для этого приложения, Enter/Tab в fallback, превышен `maxDeleteCount`, не сконструировано событие.
- `replay` не смог вернуть подавленную клавишу.
- Не найден источник раскладки для переключения в `LayoutManager.switchTo`.

**info**
- Старт/стоп монитора, смена уровня или лимита, включение и выключение захвата текста.
- Применённая коррекция: путь (`ax` / `keystroke`), проактивная или ретроактивная, длина цепочки `carry`, слово и конверсия (`Sensitive`).
- Добавлено исключение или гибридное приложение.

**debug**
- Каждая граница слова: символ границы, слово (`Sensitive`), `currentLayoutIsRussian`, вариант, решение `isWrongLayout`, а также `russianScore`/`englishScore` слова и его конверсии. Скоры считаются публичными функциями `LanguageDetector`, без фильтрации пунктуации, которую делает `isWrongLayout`. Для диагностики этого хватает, а API детектора не меняется.
- Результат `captureWordAnchor` (найден / нет, и почему: нет элемента, свой процесс, secure, не editable, слово не совпало) и `resolveCarry`.
- Результат AX-замены: отказ записи, readback не совпал, отказ установки курсора.
- Каждый сброс буфера слова или цепочки с причиной: смена приложения, клавиша без символа (с keycode), не-буквенный символ, шорткат, Backspace на пустом буфере.
- Проактивные проверки и guard'ы, на которых они остановились.

Отдельные нажатия клавиш **не** логируются: это и шум, и тот самый keylogger, от которого защищает маскирование. Сброс буфера с причиной даёт то же диагностическое знание.

Чтобы писать причину отказа AX, методы `TextFieldController` (`captureWordAnchor`, `replaceAnchoredWord`, `replace`) логируют её сами, в точке отказа. Сигнатуры не меняются.

## 6. Меню

После пунктов про исключения и гибридные приложения:

```
Показать файл исключений в Finder
─────────
Логирование                       ▸  ✓ Выключено
                                      Только ошибки
                                      Информация
                                      Отладка
                                     ─────────
                                      Макс. размер: 10 МБ
                                      Макс. размер: 50 МБ
                                    ✓ Макс. размер: 100 МБ
                                     ─────────
                                      Записывать набранный текст (30 мин)
                                     ─────────
                                      Показать лог в Finder
```

- Уровень и размер — радиогруппы (`state = .on` у выбранного). Выбор сразу применяется и сохраняется.
- «Записывать набранный текст» недоступен (`isEnabled = false`), пока уровень ниже «Информация»: на уровне ошибок текста в сообщениях нет. При включении запускается `Timer` на 30 минут, по истечении флаг снимается, меню перестраивается, в лог пишется `info`-строка об этом. Повторное включение перезапускает таймер.
- «Показать лог в Finder»: `NSWorkspace.activateFileViewerSelecting` на `latcyr.log`, а если его нет — открывается каталог `~/Library/Logs/LatCyr/` (при необходимости создаётся).
- «Показать файл исключений в Finder»: `activateFileViewerSelecting` на пользовательский `~/Library/Application Support/LatCyr/exceptions.txt`. Файл предзаполнен и в норме существует. Если его всё же нет, открывается его каталог.

## 7. Тестирование

Юнит-тесты (новые классы):
- `LogRedactorTests`: кириллица, латиница, смешанное, без букв, пустое, «ё», длина в `Character` для составных символов.
- `LogRotationTests`: `shouldRotate` на границе лимита, пустой текущий файл с длинной строкой, `filesToDelete` при уменьшении лимита, удаление от старшего индекса, ничего не удаляется при сумме в пределах.
- `LogMessageTests`: `Sensitive` в `LogMessage` маскируется при выключенном флаге и выводится как есть при включённом; `Sensitive` в обычной строке маскируется всегда.
- `LogSettingsTests` на изолированном `UserDefaults(suiteName:)`: значения по умолчанию, приведение недопустимого лимита к 100 МБ.

Вручную:
- Каждый уровень даёт ожидаемые строки. При `.off` каталог не создаётся.
- Ротация на лимите 10 МБ, например с временно уменьшенным `perFile`. Переход 100 → 10 МБ удаляет лишнее сразу.
- Захват текста снимается через 30 минут и после перезапуска.
- Набор в Safari, Terminal и Claude на уровне «Отладка» без заметной задержки ввода.

## 8. Вне рамок

- Отправка логов на сервер или автоматическая выгрузка в поддержку: пользователь прикладывает файл сам.
- Дублирование в `os_log`: для живой отладки достаточно `tail -f`.
- UI настройки времени захвата текста: 30 минут зашиты в коде, как и пороги эвристики.
