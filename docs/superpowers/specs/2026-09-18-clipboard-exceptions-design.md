# Добавление исключений через буфер обмена — Дизайн-документ

**Дата:** 2026-09-18
**Статус:** утверждён

## 1. Цель

Пункт меню «Добавить выделенное в исключения» читает выделение через `kAXSelectedTextAttribute` (`TextFieldController.selectedText`). В терминалах и Electron-приложениях — то есть ровно там, где пользователь чаще всего сталкивается с ложными срабатываниями на IT-терминах, — этот атрибут недоступен: видимый текст не является редактируемой AX-строкой. Пункт меню там всегда отвечает «Не удалось прочитать выделение», и пополнить список исключений можно только правкой файла в Finder.

Решение: когда AX-путь не сработал, получить выделенный текст через буфер обмена — послать фронтальному приложению синтетический Cmd+C, прочитать строку, восстановить прежнее содержимое буфера. Cmd+C обрабатывает само приложение, поэтому путь работает везде, где есть команда «Копировать», независимо от AX.

## 2. Требования

- Поведение в приложениях, где AX работает (Safari, TextEdit, Notes), **не меняется**: буфер обмена не трогается, синтетические события не посылаются.
- Буфер обмена пользователя восстанавливается после операции — best-effort, со всеми типами данных, какие удалось захватить снимком.
- «Копирование не удалось» отличается от «скопировалось не то»: приложение могло не иметь команды Copy, могло ничего не выделить, могло положить в буфер картинку. Все исходы сообщаются пользователю явно, ни один не проглатывается молча.
- Синтетический Cmd+C не должен ломать буфер слова `InputMonitor` и не должен вызывать коррекцию.
- Правила валидации слова (один алфавит, без цифр и пунктуации) остаются прежними и применяются к тексту из обоих источников одинаково.

## 3. Архитектура

### Новый компонент `ClipboardReader`

Тонкая обёртка над `NSPasteboard` и `CGEvent` (по аналогии с `KeystrokeSimulator`, `LayoutManager`, `PermissionManager`): системные API, чистой логики нет, тестируется вручную.

```swift
final class ClipboardReader {
    /// Копирует текущее выделение фронтального приложения синтетическим
    /// Cmd+C и возвращает пришедшую строку, восстанавливая прежнее
    /// содержимое буфера. nil — если приложение не ответило на Cmd+C
    /// за таймаут или положило в буфер не-текст.
    func copySelection(completion: @escaping (String?) -> Void)
}
```

Алгоритм:

1. **Снимок буфера.** `NSPasteboard.general.pasteboardItems` копируется глубоко: для каждого item создаётся новый `NSPasteboardItem`, в который переносятся данные по всем типам (`item.types` → `item.data(forType:)` → `setData(_:forType:)`). Глубокая копия обязательна — после `clearContents()` исходные объекты становятся недействительными.
2. **Запоминается `changeCount`.**
3. **Постится Cmd+C** — `CGEvent(keyboardEventSource: nil, virtualKey: 8 /* kVK_ANSI_C */, keyDown:)`, пара down/up с `flags = .maskCommand`, оба события помечены `KeystrokeSimulator.eventMarker`.
4. **Ожидание ответа.** `changeCount` опрашивается с шагом `pollInterval` до истечения `copyTimeout`. Изменение `changeCount` — единственный надёжный признак, что копирование произошло: `CGEvent.post` ничего не возвращает, а «в буфере лежит строка» не отличает свежую копию от того, что лежало там со вчера.
5. **Чтение и восстановление.** При изменении `changeCount` читается `string(forType: .string)`, затем буфер восстанавливается из снимка (`clearContents()` + `writeObjects(snapshot)`), и строка (или `nil`, если пришёл не-текст) отдаётся в `completion`.
6. **Таймаут.** Если `changeCount` не изменился, буфер не трогается вообще — восстанавливать нечего, а лишний `clearContents()` сбросил бы чужой лениво-предоставляемый контент. В `completion` уходит `nil`.

### Почему не через `KeystrokeSimulator`

`KeystrokeSimulator` уже умеет постить помеченные события, но переиспользован не будет: его `replay(keyCode:)` не принимает модификаторов, конструктор требует `HybridAppStore`, а сам класс документирован строго как fallback **замены текста** — работа с буфером обмена к этой ответственности не относится. Цена — около десяти строк дублирования постинга события; взамен `ClipboardReader` не зависит ни от чего. Общий у классов только `eventMarker`, и это осознанно: именно по нему `InputMonitor.handle` пропускает наш Cmd+C.

### Почему Cmd+C не ломает работу монитора

`InputMonitor.handle` проверяет `eventSourceUserData == KeystrokeSimulator.eventMarker` сразу после `guard type == .keyDown`, до любой работы с буфером слова, — помеченное событие игнорируется целиком. Дополнительная (уже существующая) страховка: события с модификаторами Cmd/Ctrl пропускаются и без метки.

### Владение

`AppDelegate` создаёт `ClipboardReader` рядом с уже имеющимся `textFieldController`. `InputMonitor` о нём не знает — путь целиком принадлежит UI-слою.

## 4. Поток в `AppDelegate`

`addSelectedWordToExceptions` сохраняет AX как первый источник и обращается к буферу только при его провале:

```
selectedText()
  ├─ строка → addNormalizedWord(строка)
  └─ nil    → clipboardReader.copySelection { text in
                 guard let text else { showAlert(«Не удалось получить…») }
                 addNormalizedWord(text)
              }
```

Общий хвост (`addNormalizedWord`) выносится в отдельный приватный метод, чтобы оба источника проходили одну и ту же валидацию и давали одни и те же сообщения.

Текст ошибки меняется: прежняя формулировка «Не удалось прочитать выделение. В терминалах и некоторых приложениях это не поддерживается» перестаёт быть правдой — терминалы теперь поддерживаются. Новая: «Не удалось получить выделенный текст. Проверьте, что слово выделено.»

## 5. Тайминг

Три настроечных параметра в `ClipboardReader`, в духе `InputMonitor.correctionDelay`:

| Параметр | Значение | Назначение |
|---|---|---|
| `focusRestoreDelay` | 0.1 s | Пауза перед постингом Cmd+C: действие пункта меню срабатывает при закрытии меню, но возврат фокуса приложению не мгновенный |
| `pollInterval` | 0.02 s | Шаг опроса `changeCount` |
| `copyTimeout` | 0.5 s | Потолок ожидания ответа приложения |

Цепочка **асинхронная** (`DispatchQueue.main.asyncAfter`), а не `Thread.sleep`. Причина не только в том, что подвешивать menu-bar приложение на полсекунды плохо: заблокировав главный поток прямо в обработчике пункта меню, мы не дали бы меню доразобраться, а фокусу — вернуться в приложение, то есть сломали бы ровно то, чего ждём. По той же причине ожидание `changeCount` — это цепочка `asyncAfter(pollInterval)`, а не цикл со сном.

Все коллбэки исполняются на главной очереди: `NSPasteboard` и `NSAlert` этого требуют.

## 6. Обработка ошибок

| Исход | Сообщение | Буфер обмена |
|---|---|---|
| AX вернул `nil`, Cmd+C не дал ответа за `copyTimeout` | «Не удалось получить выделенный текст. Проверьте, что слово выделено.» | не тронут |
| Скопировалось не-текстовое содержимое (картинка, файл) | то же | восстановлен |
| Строка получена, но это не одно слово одного алфавита | «Выделите слово на одном языке — русском или английском.» (без изменений) | восстановлен |
| Слово уже в списке | «Уже в списке исключений: `foo`» (без изменений) | восстановлен |
| Слово добавлено | «Добавлено в исключения: `foo`» (без изменений) | восстановлен |

Подтверждения перед добавлением нет — слово берётся из копии, сделанной прямо сейчас, а не из старого содержимого буфера. Итоговый алерт и служит подтверждением, как и на AX-пути: одно и то же действие меню не должно вести себя по-разному в зависимости от приложения.

## 7. Вынос валидации в чистую функцию

`AppDelegate.normalizedExceptionWord(from:)` — чистая функция, живущая приватным методом UI-класса и не покрытая тестами. С приходом буфера обмена она становится нагруженнее: из AX приходило ровно выделение, из терминала легко прилетит строка с хвостовым переводом строки или неразрывным пробелом.

Выносится без изменения поведения в отдельный файл `Sources/LatCyr/ExceptionWord.swift`:

```swift
enum ExceptionWord {
    /// Слово целиком из одного алфавита — латиницы или кириллицы (а-я и ё),
    /// в нижнем регистре и без окружающих пробелов. nil для всего
    /// остального: пустая строка, цифры, пунктуация, смешение алфавитов,
    /// несколько слов.
    static func normalized(from text: String) -> String?
}
```

`AppDelegate` вызывает `ExceptionWord.normalized(from:)`, приватный метод удаляется. Это ровно та граница «чистая функция ↔ тонкая обёртка», на которой держится весь проект: `ClipboardReader` остаётся непроверяемым системным слоем, валидация — проверяемой.

## 8. Тестирование

**Автоматические** — новый `Tests/LatCyrTests/ExceptionWordTests.swift`:
- латинское слово, кириллическое слово, слово с «ё» → принимаются;
- верхний и смешанный регистр → приводятся к нижнему;
- окружающие пробелы, табуляции, перевод строки → обрезаются (типичная копия строки из терминала);
- смешение алфавитов (`hеllo`, где «е» кириллическая) → `nil`;
- цифры, пунктуация, дефис, точка → `nil`;
- два слова через пробел → `nil`;
- пустая строка и строка из одних пробелов → `nil`.

**Ручные** — `ClipboardReader` как системная обёртка юнит-тестами не покрывается:
- Terminal.app и iTerm2: выделить слово мышью → меню → слово добавлено, буфер обмена вернулся к прежнему содержимому;
- VS Code (Electron) — то же;
- Safari и TextEdit: AX-путь по-прежнему срабатывает первым, буфер обмена не тронут;
- ничего не выделено → сообщение о неудаче, буфер не тронут;
- в буфере была картинка → после операции картинка на месте;
- в буфере был файл из Finder → после операции файл вставляется как прежде;
- выделено несколько слов → сообщение о валидации, буфер восстановлен.

## 9. Принятые ограничения

- **Лениво предоставляемые данные не восстанавливаются.** Снимок захватывает то, что приложение-источник материализует по запросу `data(forType:)`; file promises и подобные отложенные представления при восстановлении теряются. Редкий край, лечение несоразмерно сложное.
- **Приложение без команды Copy или с нестандартным шорткатом** даёт таймаут. Это сообщается пользователю явно.
- **Окно ~50 мс, когда в буфере лежит наше слово.** Если пользователь успеет вставить в другом месте именно в этот момент, он вставит слово. Теоретический край, не лечится.
- **Гонка с собственным копированием пользователя.** Если во время ожидания пользователь сам скопирует что-то, мы прочтём его содержимое и восстановим поверх старое. Край того же порядка.
- **Secure-поля.** AX-путь отсекает их сам (`TextFieldController.isSecure`), клипбоард-путь полагается на macOS, запрещающую копирование из защищённого поля: Cmd+C там просто даёт таймаут. Отдельной проверки не добавляем.
- **В терминале Cmd+C перехватывает сам эмулятор** и в PTY ничего не отправляет — в отличие от уже существующей Backspace-инъекции (`KeystrokeSimulator.correct`), этот путь TUI-программы не задевает.

## 10. Границы (out of scope)

- Глобальный хоткей для добавления исключения без захода в меню.
- Удаление и редактирование исключений из UI — по-прежнему только правка файла.
- Замена AX-пути на клипбоард целиком: AX остаётся первым источником там, где он работает.
- Использование буфера обмена где-либо ещё, кроме этого пункта меню (в частности, в самой коррекции текста).
