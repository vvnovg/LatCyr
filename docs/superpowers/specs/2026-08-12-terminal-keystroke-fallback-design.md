# Фолбэк коррекции через симуляцию клавиш для терминалов — Дизайн-документ

**Дата:** 2026-08-12
**Статус:** утверждён

## 1. Проблема

`TextFieldController` исправляет текст через Accessibility API (`AXUIElementSetAttributeValue` на `kAXValueAttribute`). Это работает для обычных Cocoa-полей, но не для терминалов (Terminal.app, iTerm2): то, что видно на экране, — рендер вывода PTY-процесса, а не редактируемая AX-строка. `AXUIElementSetAttributeValue` в терминале нередко возвращает `.success`, ничего реально не меняя.

До этого документа уже исправлено следствие: `TextFieldController.replace` перечитывает значение после записи и возвращает `false`, если оно не совпало с ожидаемым — раскладка больше не переключается поверх неисправленного текста. Но само исправление в терминале при этом не происходит вообще: слово остаётся набранным в неправильной раскладке.

Эта задача — добавить работающий путь исправления именно для терминалов.

## 2. Требования

- Исправление слова должно реально появляться в терминале (Terminal.app, iTerm2), а не только переключать раскладку.
- Работает как фолбэк: основной AX-путь пробуется первым (для всех приложений, без изменений), к симуляции клавиш переходим только если он не сработал.
- Активируется только когда активное приложение — из белого списка терминалов. Не универсальный фолбэк на все приложения: без AX-элемента нет возможности проверить `isSecure`/`isOwnApp`, включение везде было бы небезопасно (риск слепого набора в парольное поле неизвестного приложения).
- Белый список: `com.apple.Terminal` (Terminal.app), `com.googlecode.iterm2` (iTerm2).
- Инъекция клавиш не должна попадать в собственный буфер `InputMonitor` (риск порчи буфера или зацикливания).
- Известное принятое ограничение: терминалы не имеют AX-роли `AXSecureTextField`, отличить приглашение пароля (`sudo`, `ssh`) невозможно. Единственная защита — существующая эвристика `LanguageDetector` (пароли обычно не проходят как «похожее на слово»). Это не хуже текущего поведения (буфer клавиш и так накапливается при вводе в терминал) и не закрывается в рамках этой задачи.

## 3. Архитектура

### Новый компонент

| Компонент | Файл | Ответственность |
|---|---|---|
| KeystrokeSimulator | `KeystrokeSimulator.swift` | Тонкая обёртка над `CGEvent`: определяет, что активное приложение — терминал из белого списка; инжектирует Backspace × N и текст исправления как синтетические события |

Тестируется только вручную, как остальные системные обёртки (`LayoutManager`, `TextFieldController`, `PermissionManager`).

### Механизм инъекции

Используется `CGEventKeyboardSetUnicodeString` — событие клавиатуры с произвольной unicode-строкой в теле, без сопоставления символ → keycode/раскладка. Тот же приём, что у текстовых экспандеров (Espanso и т. п.).

```
KeystrokeSimulator.correct(deleting originalLength: Int, typing replacement: String) {
    repeat originalLength times:
        post synthetic keyDown+keyUp, keyCode 51 (Backspace), tagged
    post synthetic keyDown+keyUp, keyCode 0, keyboardSetUnicodeString = replacement, tagged
}
```

Каждое инжектируемое событие помечается уникальным значением через `CGEventField.eventSourceUserData` — своя метка LatCyr, отличимая от любых реальных нажатий.

### Изменение потока в InputMonitor

```
applyCorrection(word, wasRussian, replacePrefix):
    converted = конвертировать word

    если AX-путь доступен (element найден, не own app, не secure, editable):
        replaced = AX-замена (как сейчас, с readback-проверкой)
        если replaced: switchLayout(); return true

    если AX-путь не сработал И frontmost-приложение ∈ белый список терминалов:
        KeystrokeSimulator.correct(deleting: word.count, typing: converted)
        switchLayout()
        return true

    return false
```

`switchLayout` — существующий инвариант «замена → переключение», вынесенный в приватный метод, используется обеими ветками.

### Игнорирование собственных синтетических событий

`InputMonitor.handle(event:)` в самом начале проверяет метку:

```
если event.getIntegerValueField(.eventSourceUserData) == LatCyr-метка:
    return  // не трогаем буфер, событие уже наше и обработано
```

Без этой проверки: синтетический Backspace лишний раз укоротит `currentWord` (не страшно, буфер уже пуст к этому моменту, но лишняя работа), а синтетическое событие с юникод-строкой (keyCode 0) уйдёт в `layoutManager.character(forKeyCode: 0, ...)`, вернёт случайную букву текущей раскладки для этой клавиши и испортит следующий буфер слова.

## 4. Что не меняется

- Проактивный путь (`replacePrefix`) получает тот же фолбэк «бесплатно» — `applyCorrection` общий для обоих путей: удаляются `prefix.count` символов вместо всего слова.
- `TextFieldController`, `LanguageDetector`, `TextConverter` не меняются.
- Список белых терминалов — константа в коде (по аналогии с порогами `LanguageDetector` — настройки в v1 только в коде, без UI).

## 5. Тестирование

- Юнит-тестов нет — `KeystrokeSimulator` работает с системным API (`CGEvent`), тестируется только вручную.
- Ручная проверка: Terminal.app и iTerm2 — набрать слово в неправильной раскладке, убедиться, что оно заменяется на исправленное и раскладка переключается. Также проверить, что обычные Backspace/ввод пользователя (не инжектированные) по-прежнему корректно обрабатываются буфером после срабатывания фолбэка.

## 6. Хвост, набранный в окне `correctionDelay` (дополнение 2026-10-23)

**Проблема.** Фолбэк срабатывает через `correctionDelay` после граничной клавиши, и быстрый набор к этому моменту уже добавил после границы первые буквы следующего слова. Арифметика «`span.count + 1` Backspace'ов» этого не знала: на экране `ghbdtn v` она стирала `v`, пробел и `hbdtn`, печатала `привет ` — получалось `gпривет `. Хуже того, буфер слова (`currentWord`) хвост `v` хранил, хотя с экрана он пропал: следующее слово набиралось уже в переключённой раскладке (`vогда`), на его границе детектор его ловил, и фолбэк удалял `span.count + 1` = 6 символов там, где на экране стояло лишь `огда` и пробел перед ним — пробел между словами «заменялся» первой буквой второго слова (`gприветкогда`). Проявлялось только в гибридных приложениях и терминалах: AX-путь заменяет по якорю и хвост не трогает.

**Решение.** Чистый `KeystrokeFallbackPlan` (под юнит-тестами, `KeystrokeFallbackPlanTests`):
- `tail(buffer:keyDownsSinceBoundary:keyDownsInBuffer:)` — хвост известен, когда каждый `keyDown` после границы вошёл в буфер слова: `InputMonitor.keyDownsInWord` считает буквы, добавленные в `currentWord`, и Backspace'ы по непустому буферу, и сбрасывается вместе с буфером (`clearWord()`). Тогда хвост — это сам буфер (в том числе пустой: буква набрана и стёрта). Любая другая клавиша (вторая граница, стрелка, шорткат, Backspace за начало слова) делает экран неизвестным — фолбэк пропускается с `error`, раскладка не переключается.
- План: удалить `span.count + 1 + tail.count`, напечатать `converted + boundary + конверсия(tail)`. Хвост конвертируется: он набран в той же неправильной раскладке, что и слово, — раскладка переключается только после правки.
- После правки `currentWord` = конверсия хвоста, `currentLayoutIsRussian` = новая раскладка: остаток слова дописывается в тот же буфер и оценивается одним токеном. `keyDownsInWord` не меняется — это по-прежнему клавиши, из которых состоит буфер.

Enter/Tab (`applyCorrectionNow`, `boundary: nil`) и проактивный путь не затронуты: первый синхронный, у второго свой guard `currentWord == word`. Кандидат ⇧⇧ (`PendingFix.keystroke`) по-прежнему создаётся только при пустом хвосте.
